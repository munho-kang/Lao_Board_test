📝 간단한 게시판 — 배포 가이드

프론트엔드는 GitHub Pages에, 백엔드는 Render에 배포합니다.

🖥️ 프론트엔드 — GitHub Pages index.html · style.css · app.js · config.js
→
⚙️ 백엔드 — Render server.js · posts.json · /api/posts

이 가이드에 대해

두 서비스가 서로 다른 주소에서 돌아가기 때문에, 프론트엔드가 백엔드 주소를 알아야 합니다. 그래서 순서가 중요합니다 — 백엔드를 먼저 배포해서 주소를 받은 다음, 그 주소를 프론트엔드에 알려주고, 마지막에 GitHub Pages를 켭니다.

단계하는 일걸리는 시간
1수정된 코드를 GitHub에 푸시1분
2Render에 백엔드 배포 → 주소 받기5분
3config.js에 그 주소를 입력하고 푸시2분
4GitHub Pages 켜기3분
5동작 확인1분

미리 준비할 것

  • GitHub 계정 (저장소: munho-kang/Lao_Board_test)
  • Render 계정 — 없다면 2단계에서 GitHub 계정으로 바로 가입할 수 있습니다
  • 저장소가 Public일 것 — GitHub Pages 무료 플랜은 공개 저장소에서만 동작합니다

1코드를 GitHub에 푸시하기

배포 준비를 위해 수정한 코드를 먼저 올립니다. 프로젝트 폴더에서 실행하세요.

git add -A
git commit -m "배포 설정 추가"
git push origin main
푸시가 거부된다면

git pull origin main --rebase 를 먼저 실행한 뒤 다시 푸시하세요.

2Render에 백엔드 배포하기

2-1. 가입 및 서비스 생성

  1. render.com 접속 → Get Started → GitHub으로 로그인 (권한 승인)
  2. 대시보드 오른쪽 위 New + → Web Service 선택
  3. 저장소 목록에서 Lao_Board_test 를 찾아 Connect 클릭
    • 목록에 없으면 Configure account 또는 Credentials 를 눌러 해당 저장소 접근 권한을 허용하세요.

2-2. 설정값 입력

아래 표대로 입력하고 나머지는 기본값으로 두세요.

항목값설명
Namelao-board-test자유롭게 지어도 됩니다. 이 이름이 주소가 됩니다.
RegionSingapore한국에서 가장 가까워 응답이 빠릅니다.
Branchmain
Root Directory(비워둠)
Language (또는 Runtime)Node보통 자동으로 선택됩니다.
Build Commandnpm install
Start Commandnpm start
Instance TypeFree카드 등록 없이 사용 가능합니다.

맨 아래 Deploy Web Service 버튼을 누릅니다.

2-3. 배포 확인

로그 화면이 뜨고 2~5분 정도 걸립니다. 아래 두 줄이 보이면 성공입니다.

Server running on port 10000
==> Your service is live 🎉
주소 복사하기

화면 왼쪽 위, 서비스 이름 아래에 https://lao-board-test.onrender.com 형태의 주소가 표시됩니다. 이 주소를 복사해두세요. 다음 단계에서 사용합니다.

브라우저 주소창에 복사한주소/api/health 를 입력해 확인해보세요. 아래처럼 나오면 백엔드가 정상입니다.

{"status":"ok","posts":1}

3프론트엔드에 백엔드 주소 알려주기

프로젝트의 config.js 파일을 열면 아래 줄이 있습니다.

// 수정 전
const RENDER_API_URL = 'https://여기에-Render-주소를-붙여넣으세요.onrender.com';

2단계에서 복사한 주소로 바꿉니다.

// 수정 후
const RENDER_API_URL = 'https://lao-board-test.onrender.com';
주의

주소 끝에 / 나 /api 를 붙이지 마세요. https:// 로 시작해야 합니다.

저장한 뒤 다시 푸시합니다.

git add config.js
git commit -m "Render 백엔드 주소 설정"
git push origin main

4GitHub Pages 켜기

  1. GitHub 저장소 (munho-kang/Lao_Board_test) 로 이동합니다.
  2. 상단 탭에서 Settings 클릭
  3. 왼쪽 사이드바에서 Pages 클릭
  4. Build and deployment 항목에서
    • Source: Deploy from a branch
    • Branch: main 선택, 옆의 폴더는 / (root)
  5. Save 클릭
  6. 1~2분 기다린 뒤 페이지를 새로고침하면 상단에 Visit site 버튼이 나타납니다. 클릭하세요.
완성된 주소

https://munho-kang.github.io/Lao_Board_test/

Branch 목록에 main이 없다면

아직 푸시가 되지 않은 상태입니다. 1단계를 먼저 완료하세요.

5동작 확인

  1. Pages 주소를 엽니다.
  2. 게시글 목록에 "게시글을 불러오는 중입니다..." 가 잠시 표시됩니다. 첫 접속은 최대 1분까지 걸릴 수 있습니다 (아래 설명 참고).
  3. 작성자·제목·내용을 입력하고 등록을 눌러 글이 목록에 나타나는지 확인합니다.
  4. 페이지를 새로고침해도 글이 남아 있는지 확인합니다.
  5. 삭제 버튼도 눌러봅니다.
여기까지 되면 배포 완료입니다 🎉

앞으로는 git push 만 하면 GitHub Pages와 Render가 각각 자동으로 다시 배포합니다.

⚠️ 무료 플랜에서 꼭 알아야 할 두 가지

1. 15분간 접속이 없으면 서버가 잠듭니다

Render 무료 플랜은 15분 동안 요청이 없으면 서버를 중지시킵니다. 다음 접속 때 다시 켜지는데 최대 1분 정도 걸립니다. 이 시간 동안 게시판에는 "불러오는 중" 안내가 표시되니, 잠시 기다리면 정상적으로 나타납니다.

2. 서버가 재시작되면 글이 초기화됩니다

글은 서버의 posts.json 파일에 저장되는데, Render 무료 플랜의 저장 공간은 임시(ephemeral)입니다. 즉 아래 상황에서 작성한 글이 사라지고 저장소에 커밋된 초기 상태로 되돌아갑니다.

  • 코드를 푸시해서 재배포될 때
  • 서버가 잠들었다가 다시 깨어날 때
정리하면

이 게시판은 데모·테스트 용도로는 충분하지만, 글을 오래 보관하는 용도로는 쓸 수 없습니다.

글을 영구 보관하려면

나중에 필요해지면 두 가지 방법이 있습니다.

  • Render Postgres 연동 — Render에서 무료 데이터베이스를 만들고 server.js를 파일 대신 DB를 쓰도록 수정합니다. 가장 일반적인 방법입니다.
  • Render 유료 플랜 + Persistent Disk — 디스크를 붙이면 파일 저장 방식 그대로 유지됩니다. 코드 수정이 거의 없습니다.

🔧 문제 해결

증상원인과 해결 방법
"백엔드 주소가 아직 설정되지 않았습니다" config.js의 RENDER_API_URL을 수정하지 않았거나, 수정 후 푸시하지 않았습니다. 3단계를 다시 확인하세요.
"서버에 연결하지 못했습니다" 순서대로 확인하세요.
  1. 브라우저에서 Render주소/api/health 가 열리는지 — 안 열리면 Render 쪽 문제입니다. Render 대시보드의 Logs 탭을 확인하세요.
  2. config.js의 주소에 오타가 없는지, https://로 시작하는지
  3. 서버가 깨어나는 중일 수 있으니 다시 시도 버튼을 한 번 더 누르기
첫 로딩이 아주 느림 정상입니다. 무료 플랜 서버가 깨어나는 중이며 최대 1분 걸립니다.
Pages 주소가 404 배포에 1~2분 걸립니다. 그래도 안 되면 Settings → Pages에서 Branch가 main / (root)로 저장됐는지, 저장소 루트에 index.html이 있는지 확인하세요.
화면 스타일이 깨져 보임 브라우저 캐시입니다. Ctrl+Shift+R (Mac은 Cmd+Shift+R)로 강력 새로고침하세요.
콘솔에 CORS 오류 server.js에 app.use(cors())가 있는지, Render에 최신 코드가 배포됐는지 확인하세요. Render 대시보드에서 Manual Deploy → Deploy latest commit으로 강제 재배포할 수 있습니다.
Render 배포 실패 (Build failed) Logs에서 원인을 확인하세요. Start Command가 npm start인지, package.json이 저장소 루트에 있는지 확인합니다.
썼던 글이 사라짐 고장이 아니라 무료 플랜의 특성입니다. 위 무료 플랜에서 꼭 알아야 할 두 가지를 참고하세요.

📎 참고

수정 후 다시 배포하려면

git push origin main 한 번이면 끝입니다. 프론트엔드는 GitHub Pages가, 백엔드는 Render가 각각 자동으로 감지해 다시 배포합니다.

로컬에서 실행하려면

npm install
npm start
# 브라우저에서 http://localhost:3000 접속

로컬에서는 config.js가 자동으로 같은 서버(localhost:3000)의 API를 사용하므로, Render 주소를 넣어둔 상태에서도 아무것도 바꿀 필요 없이 그대로 개발할 수 있습니다.
